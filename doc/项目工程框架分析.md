# UART Service 项目工程框架分析

## 一、项目概述

这是一个**嵌入式串口-网络双向透传服务**，运行在Linux系统上的应用。主要功能是将多个串口（最多16个）的数据通过网络（TCP/UDP）进行转发，实现串口设备的远程网络化管理和控制。

目标平台：ARM Linux，编译器为 `arm-linux-gnueabihf-gcc`

## 三、核心模块详解

### 3.1 系统抽象层 (SAL)

**文件**: `system_abstraction_layer.h`, `system_abstraction_layer.c`

将VxWorks风格的API转换为Linux POSIX线程接口，实现跨RTOS的代码移植。

| VxWorks API | Linux实现 | 功能说明 |
|-----------|---------|---------|
| `taskSpawn()` | `pthread_create()` | 任务/线程创建 |
| `taskDelay()` | `nanosleep()` | 任务延时 |
| `semMCreate()` | `pthread_mutex_init()` | 互斥锁创建 |
| `semTake()` | `pthread_mutex_lock()` | 互斥锁获取 |
| `semGive()` | `pthread_mutex_unlock()` | 互斥锁释放 |
| `msgQCreate()` | 消息队列结构体 | 消息队列创建 |
| `msgQSend()` | 自定义实现 | 消息发送 |
| `msgQReceive()` | 自定义实现 | 消息接收 |

### 3.2 硬件抽象层 (HAL)

负责底层硬件访问，是连接上层应用与硬件的桥梁。

#### 3.2.1 AXI 16550 UART驱动

**文件**: `HAL/hal_axi16550.c/h`

核心驱动模块，通过PL_AXI_BASE地址映射FPGA上的UART IP核。

**地址映射**:

```
PL_AXI_BASE = 0x40000000
PL_AXI_UART_BASE = 0x41200000 (每个串口间隔0x2000)
PL_AXI_UART_SCREEN_BASE = 0x41220000 (屏幕串口)

串口n基址 = PL_AXI_UART_BASE + 0x2000 * n
```

**寄存器定义**:

| 寄存器 | 偏移 | 功能 |
|-------|------|------|
| RBR/THR | 0x1000 | 接收/发送缓冲 |
| IER | 0x1004 | 中断使能 |
| IIR/FCR | 0x1008 | 中断识别/先进先出控制 |
| LCR | 0x100C | 线缆控制 |
| MCR | 0x1010 | 调制解调器控制 |
| LSR | 0x1014 | 线缆状态 |
| MSR | 0x1018 | 调制解调器状态 |
| SCR | 0x101C | 暂存寄存器 |
| DLL/DLM | 0x1000/0x1004 | 波特率分频 |

**支持波特率**: 50 ~ 1,000,000 bps

**支持模式**: RS232, RS485(TX/RX/全双工), RS422

#### 3.2.2 其他HAL模块

| 文件 | 功能描述 |
|-----|---------|
| `hal_com.c/h` | 串口通用操作接口，封装AXI16550驱动 |
| `hal_flash.c/h` | SPI Flash读写操作，支持JFFS2文件系统 |

#### 3.3.3 网络通信模块

**文件**: `app_net_con.c`

网络连接管理器，作为整个系统的"网络总机"。

**核心职责**:

- 启动时根据全局配置初始化所有16个通道的网络服务
- 统一监听所有TCP Server端口，接受新客户端连接
- 检查并实施每个通道的最大连接数限制
- 统一管理所有TCP Client的非阻塞连接过程
- 将就绪的socket通过消息队列分发给业务任务
- 监听控制消息队列，支持动态网络模式切换

**设计原则**:

- 单一职责：只负责连接的建立、分发与计数
- 模块化：复杂逻辑分解为清晰的辅助函数
- 事件驱动：采用select()模型处理网络事件

## 四、多任务架构

应用程序创建**5个并发任务线程**：

| 优先级 | 任务名 | 线程数组 | 功能说明 |
|-------|--------|---------|---------|
| 50 | RealTimeSchedulerTask | threads[3] | 实时调度，数据转发核心 |
| 60 | ConfigTaskManager | threads[0] | 配置任务管理 |
| 75 | UdpSearchTask | threads[1] | UDP设备发现 |
| 80 | ReportManagerTask | threads[2] | 数据上报管理 |
| 90 | KeyProcessTask | - | 本地按键处理 |

**栈大小**: 32KB (DEFAULT_STACK_SIZE)

## 六、网络通信架构

### 6.1 支持的网络模式

| 模式 | 说明 |
|-----|------|
| TCP Server | 设备监听端口，客户端连接 |
| TCP Client | 设备主动连接远程服务器 |
| UDP | 无连接数据透传 |

### 6.2 端口分配策略

| 类型 | 端口范围 | 说明 |
|-----|---------|------|
| 数据端口 | 950-965 | 透传数据通道 |
| 配置端口 | 966-981 | 串口参数配置 |
| 全局配置 | 4000 | 设备全局配置 |

### 6.3 连接类型枚举


## 七、通信机制

### 7.1 消息队列

- 每个串口一个接收队列: `g_net_conn_q[16]`
- 全局配置队列: `g_config_conn_q`
- 队列深度: 24条消息 (MAX_MSG_IN_Q)

### 7.2 互斥锁

- 全局配置互斥锁: `g_config_mutex`
- 用于保护配置数据的并发访问

### 7.3 环形缓冲区

- 接收缓冲: 128KB (BUFFERCOM_SIZE_RX)
- 发送缓冲: 128KB (BUFFERCOM_SIZE_TX)

```
缓冲区大小 = NUM_PORTS * MAX_CLIENTS_PER_CHANNEL * 缓冲区长度
实际配置 = 16 * 4 * 65536 * 2 = 8MB
```

## 九、硬件规格

### 9.1 FPGA地址映射

```
0x40000000 - 0x4FFFFFFF: PL (Programmable Logic) 区域
    0x41200000: UART0-UART15 基址 (每通道 0x2000)
    0x41220000: 屏幕串口基址
```

### 9.2 UART寄存器

- 基础时钟: 29.4912MHz (AXI_16550_CLK) 或 32MHz (AXI_16550_CLK1)
- 波特率分频: DLL/DLM寄存器
- 支持FIFO: 16字节深度

## 十一、设计特点

1. **跨平台移植性**: 通过SAL层抽象，可在VxWorks和Linux间移植
2. **模块化设计**: 各功能模块职责清晰，低耦合高内聚
3. **多线程架构**: 利用POSIX线程实现并发处理
4. **事件驱动**: select()模型高效处理网络I/O
5. **实时性**: 支持实时调度任务，保证数据转发延迟
6. **可配置性**: 支持多种网络模式和端口配置
7. **本地交互**: 集成屏幕UI，支持本地配置管理
