# LED内存映射测试程序

## 用途
测试PL LED的内存映射和寄存器操作，诊断为什么`devmem`可以工作但代码中不行。

## 编译和运行

### 1. 编译
```bash
cd /path/to/test
chmod +x compile_led_test.sh
./compile_led_test.sh
```

或者直接编译：
```bash
gcc -o test_led test_led.c -Wall -Wextra
```

### 2. 运行
```bash
sudo ./test_led
```

**重要：必须以root权限运行！**

## 测试内容

程序会依次执行以下测试：

1. **打开/dev/mem** - 检查权限
2. **映射物理地址** - 0x40000000（64KB）
3. **测试读取** - 读取基地址内容
4. **计算寄存器地址** - 0x130（接收LED）、0x280（IIC触发）
5. **写入接收LED** - 点亮LED
6. **触发IIC寄存器** - 执行触发序列
7. **测试其他LED** - 发送LED、锁定LED
8. **清除所有LED** - 恢复初始状态

## 故障排除

### 问题1：打开/dev/mem失败
```
[错误] 打开/dev/mem失败: Permission denied
```
**解决方案：** 使用`sudo`运行程序

### 问题2：mmap失败
```
[错误] mmap失败: Invalid argument
```
**可能原因：**
1. 物理地址不正确
2. 地址未对齐（必须页面对齐）
3. 系统不支持该地址映射

### 问题3：写入后LED无反应
如果测试程序执行成功但LED不亮：

1. **检查硬件连接**
2. **检查物理地址**：确认0x40000000是否正确
3. **检查偏移量**：确认0x130、0x280是否正确
4. **查看内核日志**：`dmesg | tail -20`

### 问题4：与现有代码对比
现有代码中的问题：
```c
// 现有代码（可能有问题）
sysAxiWriteLong((int32_t)pl_led_base_addr + reg_address, value);

// 测试代码（正确方式）
volatile uint32_t *reg = (volatile uint32_t *)((char *)mapped_base + offset);
*reg = value;
```

## 进一步调试

如果测试程序工作正常，但现有代码不行，可以：

1. **在现有代码中添加调试输出**
2. **检查`init_pl_memory_access()`是否被调用**
3. **检查`pl_led_base_addr`的值**
4. **比较测试程序和现有代码的地址计算方式**

## 物理地址映射表

| 寄存器 | 偏移 | 物理地址 | 用途 |
|--------|------|----------|------|
| 锁定LED | 0x30 | 0x40000030 | 端口锁定状态 |
| 接收LED | 0x130 | 0x40000130 | 数据接收指示 |
| 发送LED | 0x230 | 0x40000230 | 数据发送指示 |
| 设备锁定LED | 0x270 | 0x40000270 | 设备锁定状态 |
| IIC触发 | 0x280 | 0x40000280 | 触发信号 |

## 注意事项

1. **必须root权限**
2. **地址必须页面对齐**（0x40000000已对齐）
3. **映射大小至少为最大偏移+4**（0x280+4=0x284 < 0x10000）
4. **写入后可能需要触发信号**（IIC寄存器）
