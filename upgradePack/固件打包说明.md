# 固件打包使用说明

## 概述

`firmware_packer.py` 是一个用于打包固件的工具，支持独立打包 Bitstream、OS、App 三个组件，并生成符合设备协议的固件包（`.pkg` 文件）。

## 固件包结构

```
┌──────────────────────────────────────────────────────────────┐
│                    固件包结构                                 │
├──────────────────────────────────────────────────────────────┤
│  Package Header (256 字节)                                   │
│  ├── magic_number: 0x55504454                               │
│  ├── header_crc32                                           │
│  ├── update_flags: 升级标志位                                │
│  │     bit0: 更新 Bitstream                                  │
│  │     bit1: 更新 OS                                         │
│  │     bit2: 更新 App                                        │
│  ├── pkg_version, bit_version, os_version, app_version      │
│  ├── timestamp                                               │
│  ├── bit_length, bit_crc32                                  │
│  ├── os_length, os_crc32                                    │
│  ├── app_length, app_crc32                                  │
│  └── reserved (88 字节)                                     │
├──────────────────────────────────────────────────────────────┤
│  Bitstream Data (可选)                                       │
├──────────────────────────────────────────────────────────────┤
│  OS Data (可选)                                              │
├──────────────────────────────────────────────────────────────┤
│  App Data (可选)                                             │
└──────────────────────────────────────────────────────────────┘
```

## 使用方法

### 基本语法

```bash
python firmware_packer.py [选项] -o 输出文件.pkg
```

### 选项说明

| 选项 | 简写 | 说明 |
|------|------|------|
| `--bitstream` | `-b` | Bitstream 文件路径 (FPGA 配置文件) |
| `--os` | `-o` | OS 文件路径 (VxWorks 操作系统) |
| `--app` | `-a` | App 文件路径 (应用程序) |
| `--output` | 必需 | 输出固件包文件路径 |
| `--pkg-version` | - | 固件包版本号 (默认: v1.0.0) |
| `--bit-version` | - | Bitstream 版本号 (默认: v1.0.0) |
| `--os-version` | - | OS 版本号 (默认: v1.0.0) |
| `--app-version` | - | App 版本号 (默认: v1.0.0) |

## 使用示例

### 1. 打包所有组件（完整升级）

```bash
python firmware_packer.py \
    --bitstream bitstream.bin \
    --os os.bin \
    --app app.bin \
    --pkg-version v1.0.1 \
    --bit-version v1.0.1 \
    --os-version v1.0.1 \
    --app-version v1.0.1 \
    -o update_full.pkg
```

### 2. 只打包 Bitstream（单独升级 FPGA）

```bash
python firmware_packer.py \
    --bitstream bitstream.bin \
    --bit-version v1.0.2 \
    -o bitstream_only.pkg
```

### 3. 只打包 OS（单独升级操作系统）

```bash
python firmware_packer.py \
    --os os.bin \
    --os-version v1.0.2 \
    -o os_only.pkg
```

### 4. 只打包 App（单独升级应用程序）

```bash
python firmware_packer.py \
    --app app.bin \
    --app-version v1.0.2 \
    -o app_only.pkg
```

### 5. 打包 Bitstream 和 OS

```bash
python firmware_packer.py \
    --bitstream bitstream.bin \
    --os os.bin \
    -o bit_os.pkg
```

## 升级标志位

打包工具会根据指定的组件自动设置升级标志位：

| 组件组合 | update_flags | 二进制 | 说明 |
|---------|--------------|--------|------|
| Bitstream | 0x01 | 00000001 | 只升级 Bitstream |
| OS | 0x02 | 00000010 | 只升级 OS |
| App | 0x04 | 00000100 | 只升级 App |
| Bitstream + OS | 0x03 | 00000011 | 升级 Bitstream 和 OS |
| Bitstream + App | 0x05 | 00000101 | 升级 Bitstream 和 App |
| OS + App | 0x06 | 00000110 | 升级 OS 和 App |
| Bitstream + OS + App | 0x07 | 00000111 | 升级所有组件 |

## 固件包验证

设备端会进行以下校验：

1. **Magic Number 校验**：验证是否为有效的固件包
2. **Header CRC 校验**：验证头部完整性
3. **总大小校验**：验证文件大小是否匹配
4. **Bitstream CRC 校验**（如果包含）：验证 Bitstream 完整性
5. **OS CRC 校验**（如果包含）：验证 OS 完整性
6. **App CRC 校验**（如果包含）：验证 App 完整性

## Flash 地址映射

打包后的固件包会被写入 Flash 的 B 区：

| 组件 | Flash 地址 | 大小 |
|------|-----------|------|
| Bitstream B | 0x00E80000 | 5MB |
| OS B | 0x01380000 | 3MB |
| App B | 0x01680000 | 1MB |

## 常见问题

### Q: 为什么需要打包工具？

A: 打包工具负责：
- 生成符合协议的固件包头部
- 计算各组件的 CRC32 校验和
- 设置正确的升级标志位
- 确保固件包格式正确

### Q: 可以混合不同版本的组件吗？

A: 可以。每个组件都有独立的版本号，可以单独指定。例如：
```bash
python firmware_packer.py \
    --bitstream bitstream_v1.0.1.bin \
    --bit-version v1.0.1 \
    --os os_v1.0.2.bin \
    --os-version v1.0.2 \
    --app app_v1.0.0.bin \
    --app-version v1.0.0 \
    -o mixed.pkg
```

### Q: 固件包大小有限制吗？

A: 设备端最大支持 20MB 的固件包（`MAX_PACKAGE_SIZE`）。

### Q: 如何验证打包的固件包是否正确？

A: 可以使用以下方法：
1. 检查打包工具输出的 CRC32 值
2. 使用十六进制编辑器查看文件头部的 Magic Number (0x55 50 44 54)
3. 在设备上运行升级，观察校验日志

## 技术细节

### CRC32 算法

打包工具使用 zlib 的 CRC32 算法，与 U-Boot 和设备端使用的算法一致。

### 字节序

固件包使用小端序（Little-Endian）存储多字节数据。

### 时间戳

时间戳使用 Unix 时间戳（从 1970-01-01 00:00:00 UTC 开始的秒数）。
